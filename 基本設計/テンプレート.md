## 3. ハードウェア・仮想リソース設計
### 3.1 割り当てスペック
* 本システム（各ノード）に割り当てるコンピューティングリソースを定義する。

| 項目 | スペック / 設定値 | 備考 |
| :--- | :--- | :--- |
| vCPU | X Cores | |
| vRAM | X GB | |
| vDisk | X GB | OS / データ / ログ領域 |
| vNIC | X 系統 | |

### 3.2 サイジング根拠
本システムに割り当てるリソースの選定根拠を以下に示す。

* **vCPU / vRAM 算出根拠**:
  * **想定負荷・接続数**: 同時アクセス数 〇〇 req/sec（最大想定〇〇件）を基準に算出。
  * **推奨スペック**: 利用するミドルウェア（〇〇）のメーカー推奨スペック（最小: 2Core / 4GB、推奨: 4Core / 8GB）に準拠。
  * **バッファ**: 将来的な負荷変動およびピーク時スパイクを考慮し、推奨スペックの〇倍（または＋2Core）の余裕を持たせた設計とする。
* **ディスク容量（vDisk）算出根拠**:
  * **OS・ミドルウェア領域**: 20 GB（固定）
  * **データ保存領域**: 1日あたり約 〇 GB × 365日 ＝ 〇 GB
  * **ログ領域**: ログ出力 〇 MB/日 × 保持期間（90日）＋ ローテーションバッファ ＝ 〇 GB
  * **安全係数**: 上記合計に 1.2〜1.5 倍の安全率を乗じて算定。

## 7. 非機能要件に対する設計
### 7.1 可用性設計
* 冗長化方式（Active/Standby、Active/Active、CARP/pfsync、Proxmox HA等）、フェイルオーバー条件、復旧目標を定義する。

### 7.2 性能・拡張性設計
* 処理能力、帯域幅、将来的なリソース追加（スケールアップ/スケールアウト）の方針を定義する。

### 7.3 セキュリティ
* 通信暗号化、不要サービスの停止、管理者アクセスの限定方針等を定義する。

### 7.4 バックアップ・リストア設計
* バックアップ対象データ、取得タイミング、世代管理、リストア手順を記述する。

### 7.5 ログ管理設計
* 出力するログの種類、保存場所、ローテーションルール、外部転送（Syslog等）の具体設定を記述する。

### 7.6 監視設計
* 死活監視（Ping等）、リソース監視（CPU/メモリ/ディスク）、プロセス・サービス状態監視の項目と閾値を記述する。

### 7.7 移行性設計
* 新システムへの切り替えに伴う移行対象データ、移行方式（一括/段階）、移行手順および切り戻し方針を記述する。
