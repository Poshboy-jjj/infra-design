# 運用設計書（ホームラボ環境）

## 1. 運用方針・運用体制
* **運用目的**: ホームラボ環境（検証・開発・各種自作サービス）の安定稼働および迅速な障害復旧
* **運用体制**: 
  * **一次対応・管理責任者**: ラボ管理者（セルフオペレーション）
  * **サービスレベル目標（SLA）**: ベストエフォート（24時間365日無停止保証は無し。計画停止・臨時メンテナンスを許容）

---

## 2. システム運用（日常運用）

### 2.1 起動・停止手順
* **通常起動順序**:
  1. 物理ネットワーク機器（ルータ・L2/L3スイッチ）
  2. 物理ストレージ / 共有NAS（NFS/iSCSI等）
  3. 物理ハイパーバイザー（VMware ESXi / Proxmox / Nutanix等）
  4. 共通インフラDNS/NTP/DHCP・認証・Tailscaleサブネットルータ
  5. 統合監視（Zabbix / Prometheus等）
  6. 一般VM / コンテナ / 各種サービス（Home Assistant、メディア系等）
* **通常停止順序**:
  * 起動順序の完全逆順（サービスVM停止 ➔ ハイパーバイザーシャットダウン ➔ ストレージ ➔ NW）

### 2.2 バックアップ・リストア運用
* **バックアップ対象**:
  * VM/コンテナ設定ファイル（Docker Compose、Ansible Playbook、Gitリポジトリ）
  * データベースデータ（定期ダンプ）
  * ハイパーバイザー・ネットワーク機器の設定バックアップ（Exportファイル）
* **スケジュール / 世代管理**:
  * **設定・コード類**: GitHub / GitLabへ随時Commit & Push
  * **DB / 設定ファイル**: 日次（`03:00`）バックアップ、ローカル世代保持（7世代）
  * **VMスナップショット**: 大規模変更前の手動取得（変更完了後に削除）
* **保管場所**: ローカルストレージ ＋ 外部（クラウドストレージ or 別物理NAS）

---

## 3. 保守・変更管理（ライフサイクル運用）

### 3.1 アップデート・パッチ適用方針
* **OS / パッケージ**:
  * マイナーアップデート・セキュリティパッチ: 月1回（または脆弱性発見時に随時手動適用）
  * 自動更新: 不意のサービス停止を防ぐため、原則「無効（手動検証後適用）」
* **ハイパーバイザー / FWファームウェア**:
  * 年1〜2回の計画メンテナンス時に一括適用

### 3.2 構成管理・IaC方針
* **設定変更ルール**:
  * コード化可能な構成（Docker, K8s, OS設定）は Ansible / Terraform / Git にて管理（IaC化）
  * 物理NWやハイパーバイザー等のGUI手動変更時は、構成変更ログ（Git commitログやWiki）に残す

---

## 4. 障害・ログ・監視運用

### 4.1 障害検知・通知フロー
* **検知手段**: 統合監視（Zabbix / Prometheus + Grafana）による死活・リソース監視
* **障害通知**: 
  * **重要度【High / Critical】**: スマホ通知（Discord / Slack / Telegram webhook 等）へリアルタイム送信
  * **重要度【Info / Warning】**: ダッシュボード確認のみ

### 4.2 一次切り分け・復旧対応手順
1. **影響範囲特定**: 死活監視（Ping / HTTP）で障害対象（物理/VM/NW）の特定
2. **遠隔アクセス確保**: VPN（Tailscale等）経由で管理コンソール（iDRAC/iLO/IPMI、SSH）へ接続
3. **ログ確認**: `/var/log/messages`, `journald`, `docker logs` 等の確認
4. **簡易復旧アクション**:
   * 該当サービス・コンテナの再起動
   * VMの再起動
   * バックアップからのリストア（設定ファイル・DB）

---

## 5. 停電・電源保護（UPS）運用
* **電源保護構成**: UPS（無停電電源装置）接続（主要物理サーバ・NAS・核心NW機器）
* **自動シャットダウン閾値**:
  * 停電検知後、バッテリー残量 30% 以下（または停電継続 5分経過）でシャットダウンシーケンスを自動実行（NUT / PowerChute 等）
