# 利用するソフトウェア
仮想基盤はProxmox一択。Linuxはどうしよう。

RHEL互換のAlmaLinux　or RockyLinuxが候補だが、比較すると以下のよう。

AlmaLinux：開発はメインの1社。。有償サポート。パッチ配布などが早い

RockyLinux：数社で開発。コミュニティがオープンで盛ん。パッチ配布はAlmaLinuxに比べて遅め

上記踏まえてコミュニティが盛んという点でRockyLinuxをチョイス。ナレッジ探しやすそうなので。

Web/APサーバ：Apache/PHP→ブログサービス用

DBサーバ：PostgreSQL→Webに同じ。別居の構成をとる

ファイアウォール：OPNsence(pfsenceより新しい)→VM間通信やインターネット-VM間などをフィルタリングする。外部からOPNsenseのVPNに接続し、FWルールを介して各VLANへルーティング

DNS/NTP/認証：Bind(FreeIPAに包含)/Chrony/FreeIPA(RHELのIdM互換。OpenLDAPも使えるが、今後を考えてのこと。LinuxのADサーバ的な)→内部VMの名前解決およびフォワードでインターネットの名前解決もやる(これは仮)。あとは時刻同期とディレクトリユーザで各VMに認証する。Proxmoxも認証使いたいなあ

メールサーバ：Postfix→ZabbixからGmail通知

監視サーバ：Zabbix/Apache/PHP/PostgreSQL→死活監視など。要検討

# 構成
Proxmox　VE：1台

Web/APサーバ：どうしようかな。2台でHAにするか、HAProxy入れてLBにするか。LBだとLBがSPOFになってしまう。
段階的に構成するのであれば、最初は1台にして、リソースみてHA→LBにしていこうか。LB構成だとWebサーバにPacemakerが不要になるので削除する。
HA、LB構成で2台。今回は1台とする

DBサーバ：これも冗長化したいのでゆくゆくは2台だが、今回は1台とする。HAの場合はPacemakerを使うとして、PostgreSQLのレプリケーションかDRBDかは要検討

ファイアウォール：1台。ゆくゆくは2台

監視サーバ：1台。将来的にHAはしない

# ネットワーク
コンセプトに沿ったセグメント分けにしたいが、何をどこに置くか難しい。
管理セグメントの踏み台にVPNでアクセスしてルーティングによって各VMにSSHログインする

基本は3セグメント＋管理の分割。Untrasted、DMZ、Trasted、管理

本番環境は10.0.xx.xx/24、検証環境は192.168.xx.xx/24とする

セグメントルール

本番環境：第三オクテット＝VLAN ID

検証環境：第三オクテット＝VLAN ID下2桁

・仮想基盤：管理

本番環境：VLAN10、10.0.10.xx/24

検証環境：VLAN110、192.168.10.xx/24

・Web、Mail：DMZ

本番環境：VLAN20、10.0.20.xx/24

検証環境：VLAN120、192.168.20.xx/24

・DB：Trasted

本番環境：VLAN30、10.0.30.xx/24

検証環境：VLAN130、192.168.30.xx/24

・ファイアウォールWAN側：Untrasted

本番環境：VLAN99、10.0.99.xx/24

検証環境：VLAN199、192.168.99.xx/24

・監視・DNS/NTP/認証：Trasted

本番環境：VLAN40、10.0.40.xx/24

検証環境：VLAN140、192.168.40.xx/24

# OPNsence
用途はFWとルーティングとVPN。IXあるけどそっちは使わない(厳密にはIXはVLAN全通ししてOPNsenceでルーティングなどする)

通信の流れ

インターネット→ProxmoxのNIC→OPNsence→VM
VM→OPNsence→VM
